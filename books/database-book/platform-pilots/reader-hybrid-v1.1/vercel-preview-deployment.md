# Vercel Preview Deployment Guide — Reader Hybrid v1.1

Use this guide to test reader changes on a live Vercel preview URL **without touching production**.

| Item                   | Value                                                     |
| ---------------------- | --------------------------------------------------------- |
| Production URL         | `https://data-pilot.dimapublishing.com/`                  |
| Reader app folder      | `books/database-book/platform-pilots/reader-hybrid-v1.1/` |
| Production branch      | `main`                                                    |
| Preview branch example | `reader-polish-preview`                                   |
| Preview URL            | Auto-generated by Vercel for each branch push             |

---

## Core Concept

```
main (stable) ───────────────────────────────► production
  │                                             data-pilot.dimapublishing.com
  │
  └── reader-polish-preview ─────────────────► Vercel preview URL
        │
        └── test changes here first
```

A branch is a safe copy of the project timeline. Changes on the branch do **not** affect `main` or production until you explicitly merge them.

---

## When to Use This

Use this workflow when testing reader changes such as:

- fixing chapter titles;
- improving homepage or dashboard language;
- changing reader layout;
- updating sidebar behavior;
- improving responsive video, image, or table styling;
- changing reading-time logic;
- testing build-script cleanup rules.

Do **not** test major reader changes directly on `main`.

## Step-by-Step in VS Code

### 1. Open the full repository

In VS Code:

```
File → Open Folder...
```

Open the full repository folder:

```
dima-publishing
```

Do **not** open only the `reader-hybrid-v1.1` folder. Opening the full repo makes Git branch management clearer.

---

### 2. Check your current branch

Look at the **bottom-left corner** of VS Code.

It should say:

```
main
```

This is your safety check.

---

### 3. Create a preview branch

1. Click the branch name in the bottom-left corner.
2. Choose **Create new branch...**
3. Name the branch:

```
reader-polish-preview
```

4. Create it from:

```
main
```

VS Code should automatically switch you to the new branch.

---

### 4. Confirm the branch before editing

Before making changes, check the bottom-left corner again.

It should say:

```
reader-polish-preview
```

Do not proceed unless you are on the preview branch.

books/database-book/platform-pilots/reader-hybrid-v1.1/

## Do Not Edit This File Directly

```
src/generated/bookData.ts
```

This file is generated by:

```
scripts/generateBookData.ts
```

Treat `bookData.ts` as build output, not as the manuscript. Edit the Markdown source files or the generator script, then regenerate.

## Review and Commit Changes

### 1. Open Source Control

Click the Source Control icon in the left sidebar.

Review the changed files before committing.

### 2. Stage changes

Click the `+` next to each file you want to include, or stage all changes.

### 3. Commit

Use a clear commit message, such as:

```
Reader polish preview
```

or:

```
Fix reader title, navigation, and responsive media
```

Click **Commit**.

---

## Publish the Branch

After committing, VS Code should show:

```
Publish Branch
```

Click it.

This uploads the branch to GitHub. Vercel should detect the branch and create a Preview Deployment automatically.

---

## Find the Vercel Preview URL

Go to Vercel:

```
Vercel → data-pilot project → Deployments
```

Find the deployment for:

```
reader-polish-preview
```

Click **Visit**.

The preview URL will look something like:

```
https://data-pilot-git-reader-polish-preview-...vercel.app
```

Use that URL to review the changes.

---

## Iterate Safely

To keep testing:

```
edit files → review diff → stage → commit → push/sync → review Vercel preview
```

Vercel will rebuild the preview after each push to the branch.

Production remains unchanged until the branch is merged into `main`.

---

## Approve and Merge

Only merge after reviewing the preview.

Recommended approach:

1. Open a Pull Request from `reader-polish-preview` into `main`.
2. Review the changed files.
3. Confirm the Vercel preview looks correct.
4. Merge the Pull Request.
5. Vercel deploys the updated `main` branch to production.

Production URL:

```
https://data-pilot.dimapublishing.com/
```

---

## What Not to Do

| Do not                                                | Why                                                |
| ----------------------------------------------------- | -------------------------------------------------- |
| Edit while VS Code says `main`                        | Changes may go directly into the production branch |
| Manually edit `src/generated/bookData.ts`             | It is generated output                             |
| Merge before reviewing the preview                    | That can push unfinished changes to production     |
| Use production deployment commands from a test branch | That can bypass the safe preview workflow          |
| Save important instructions only in Copilot memory    | Put durable docs inside the repo                   |

---

## Panic Rules

### I made changes on the wrong branch

Do not commit yet.

Create a new branch from the current changes or stash the changes before switching branches.

### VS Code will not let me switch branches

You probably have uncommitted changes. Commit, stash, or discard them before switching.

### I want to abandon the preview branch

Switch back to `main`, then delete the branch later after confirming you do not need the changes.

### The preview looks wrong

Do not merge. Keep editing the preview branch until it looks right.
