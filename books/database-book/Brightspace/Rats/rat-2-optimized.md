## Multi-Select Questions

**Q1. Five-Component Framework — POS System Failure**

*Short description: Five-component failure*

A coffee shop owner installs new point-of-sale software but does not train staff, update inventory processes, or define data entry standards. Six months later, reports are inconsistent and staff do not trust the numbers.

Select ALL that apply.

A. Neglecting the people and processes components of the five-component framework  ← ✓ CORRECT
*Feedback: Correct — the five-component framework includes hardware, software, data, processes, and people. Installing software without training (people) and defined workflows (processes) means two components were neglected.*

B. The software is defective and must be replaced
*Feedback: Incorrect — the scenario does not describe a software defect; it describes missing organizational components around the software.*

C. Confusing IT (the software) with IS (the full system)  ← ✓ CORRECT
*Feedback: Correct — the owner treated buying software as building an information system, but IS requires all five components working together.*

D. A strategic alignment failure — the software does not fit the business
*Feedback: Incorrect — the scenario does not indicate the software is misaligned with business strategy; the issue is incomplete implementation.*

E. A failure of data quality because of inconsistent data entry  ← ✓ CORRECT
*Feedback: Correct — without defined data entry standards, inconsistent entries produce unreliable reports — a data quality problem.*

**Hint:** Think about which components of an information system extend beyond the software itself.

**Explanation:** Installing software without processes, training, and data standards is confusing IT with IS. The five-component framework (hardware, software, data, processes, people) shows that missing people and processes causes system failure. Inconsistent entries are a data quality problem — all three are correct diagnoses of this scenario.

**Points:** 2 | **Difficulty:** 4/5 | **ID:** BITM330-RAT2-Q1 | **Bloom:** Analyze

**Q2. DIKW Hierarchy — Monthly Sales Report**

*Short description: DIKW hierarchy*

A regional manager receives a spreadsheet showing that "Region A sold 1,247 units last month." The manager needs to determine whether performance is improving or declining.

Select ALL that apply.

A. The number 1,247 is data — it has no context, comparison, or interpretation by itself  ← ✓ CORRECT
*Feedback: Correct — data is raw facts without context. A single number with no comparison point is data, not information.*

B. The number 1,247 is already information because it describes a business result
*Feedback: Incorrect — the chapter defines information as data placed in context. A standalone number without comparison lacks context.*

C. Adding last month's figure of 1,103 units transforms data into information by providing context  ← ✓ CORRECT
*Feedback: Correct — placing data in relation to other data (comparison, trend) creates context, which transforms data into information in the DIKW hierarchy.*

D. The manager already has knowledge because they can read the spreadsheet
*Feedback: Incorrect — knowledge requires synthesis and pattern recognition across multiple information sources, not just reading one data point.*

E. Wisdom would require the manager to combine this information with strategic goals and market conditions to decide what action to take  ← ✓ CORRECT
*Feedback: Correct — wisdom is the highest DIKW level, involving judgment about what to do with information in light of broader goals.*

**Hint:** Trace the DIKW levels: where does a raw number sit? What transforms it upward?

**Explanation:** The DIKW hierarchy (Data → Information → Knowledge → Wisdom) is a core concept in Chapter 2. Raw numbers without context are data. Adding comparison (last month's figure) provides context, creating information. Knowledge requires synthesis across sources. Wisdom involves strategic judgment about what action to take.

**Points:** 2 | **Difficulty:** 4/5 | **ID:** BITM330-RAT2-Q2 | **Bloom:** Analyze

**Q3. R.E.A.D. Framework — Weekly Sales Spreadsheet**

*Short description: Data quality assessment*

An analyst opens a weekly sales spreadsheet that the team has used for months. Which action best demonstrates the "Assess" step of the R.E.A.D. framework described in Chapter 2?

A. Pulling the spreadsheet from the shared drive and opening it
*Feedback: Incorrect — this is more like the Recognize step: identifying what data is available and where it lives.*

B. Checking whether the "Total Sales" column formula is still correct and that no rows were accidentally deleted  ← ✓ CORRECT
*Feedback: Correct — Assess means evaluating data quality: checking accuracy, completeness, and consistency before using the data.*

C. Creating a pivot table to summarize sales by product category
*Feedback: Incorrect — this is closer to the Decide/Deploy step: using the data for analysis after it has been verified.*

D. Emailing the spreadsheet to the regional director with a summary paragraph
*Feedback: Incorrect — sharing results is a communication step, not an assessment of data quality.*

**Hint:** Which R.E.A.D. step is about verifying data quality before using it?

**Explanation:** Chapter 2 introduces the R.E.A.D. framework: Recognize what data is available, Evaluate/Assess its quality, Analyze it for patterns, and Decide or Deploy actions based on it. Checking formula accuracy and data completeness is the Assess step — verifying quality before analysis.

**Points:** 1 | **Difficulty:** 3/5 | **ID:** BITM330-RAT2-Q3 | **Bloom:** Apply

**Q4. Input-Process-Output Model — University Application**

*Short description: Process KPI selection*

A university admissions office receives applications (input), reviews them against criteria (process), and sends acceptance letters (output). According to Chapter 2's IPO model, which of the following would be the most appropriate KPI for measuring the PROCESS component?

A. Number of applications received per semester
*Feedback: Incorrect — this measures input volume, not process performance.*

B. Average number of days from application submission to decision letter  ← ✓ CORRECT
*Feedback: Correct — this measures the throughput speed of the process itself: how efficiently inputs are transformed into outputs.*

C. Percentage of accepted students who enroll
*Feedback: Incorrect — this is an output/outcome metric measuring what happens after the process completes.*

D. Total number of acceptance letters mailed
*Feedback: Incorrect — this is a raw output count, not a measure of process efficiency.*

**Hint:** Process KPIs measure how efficiently inputs are transformed — think about speed, cost, or quality of the transformation itself.

**Explanation:** Chapter 2's IPO model (Input → Process → Output) maps to different KPI types. Input KPIs measure what comes in (application count). Process KPIs measure the transformation (processing time). Output KPIs measure what comes out (acceptance count). Outcome KPIs measure downstream results (enrollment rate). Average processing time is the clear process KPI.

**Points:** 1 | **Difficulty:** 3/5 | **ID:** BITM330-RAT2-Q4 | **Bloom:** Apply

**Q5. KPI Design — Call Center Trap**

*Short description: KPI distortion*

A call center introduces a KPI that rewards agents for the shortest average call time. Within weeks, agents start hanging up on complex calls and rushing customers off the phone. What Chapter 2 principle does this scenario best illustrate?

A. KPIs should always measure efficiency, not effectiveness
*Feedback: Incorrect — Chapter 2 emphasizes that both efficiency AND effectiveness matter, and KPIs should balance both.*

B. The five-component framework failed because the phone hardware was outdated
*Feedback: Incorrect — the scenario describes a KPI design problem, not a hardware or technology failure.*

C. KPIs shape behavior, and poorly designed KPIs encourage behaviors that undermine the real goal  ← ✓ CORRECT
*Feedback: Correct — Chapter 2 warns that what you measure drives what people do. A KPI targeting speed alone incentivizes speed at the expense of quality.*

D. Data quality suffered because agents entered incorrect call durations
*Feedback: Incorrect — the issue is not inaccurate data entry but the incentive structure created by the KPI design.*

**Hint:** What does Chapter 2 say about the relationship between what you measure and how people behave?

**Explanation:** Chapter 2's discussion of KPIs emphasizes that "what you measure drives what people do." A KPI that only rewards speed will produce fast but low-quality interactions. Good KPI design balances efficiency (speed) with effectiveness (resolution quality) to avoid behavior distortion.

**Points:** 1 | **Difficulty:** 4/5 | **ID:** BITM330-RAT2-Q5 | **Bloom:** Analyze

**Q6. Data-to-Performance Chain — Broken Link**

*Short description: Chain link failure*

A retail chain's dashboard shows sales are "up 12%" but the underlying transaction data has duplicate entries from a system migration error. Using Chapter 2's Data-to-Performance Chain, which link is broken?

A. The Performance link — because the dashboard metric is wrong
*Feedback: Incorrect — the dashboard metric is a symptom, but the chain failure is upstream.*

B. The Decision link — because managers will make bad decisions
*Feedback: Incorrect — bad decisions would be a downstream consequence of the broken link, not the broken link itself.*

C. The Data link — because the raw transaction data is unreliable due to duplicate entries  ← ✓ CORRECT
*Feedback: Correct — the Data-to-Performance Chain starts with data quality. If raw data is corrupted, every downstream link (information, knowledge, decisions, performance) is compromised.*

D. The Analytics link — because the dashboard calculated the percentage incorrectly
*Feedback: Incorrect — the calculation is correct (12% of corrupted data); the problem is the data feeding the calculation.*

**Hint:** Follow the chain from left to right: Data → ? → ? → ? → Performance. Where does the problem originate?

**Explanation:** Chapter 2's Data-to-Performance Chain traces how raw data becomes business performance: Data → Information → Knowledge → Decisions → Performance. When raw transaction data has duplicates, the entire chain is compromised from the start. Fixing the dashboard display (Performance link) without fixing the data is treating a symptom, not the cause.

**Points:** 1 | **Difficulty:** 4/5 | **ID:** BITM330-RAT2-Q6 | **Bloom:** Analyze

**Q7. Hospital Patient Records Adoption Failure**

A hospital implements a new patient-records system. The hardware is reliable and the software functions correctly, but doctors resist using it because it adds 12 minutes of data entry per patient visit with no perceived benefit to care quality. Which component(s) of the five-component framework explain the failure?

A. Software only
*Feedback: Incorrect — the software is working correctly; the issue is organizational.*

B. Data only
*Feedback: Incorrect — there is no data quality or representation issue described; the issue is data entry workflows.*

C. Hardware only
*Feedback: Incorrect — the hardware is described as reliable.*

D. Processes and people  ← ✓ CORRECT
*Feedback: Correct — all five components must work together. A process that adds 12 extra minutes of data entry is poorly designed, and people (doctors) resist because they see no care quality benefit.*

**Hint:** Think about the non-technical components of the five-component framework.

**Explanation:** All five components of an information system (hardware, software, data, processes, and people) must work together. The process (12 extra minutes of data entry) is poorly designed, and people (doctors) resist because they see no benefit — a process and people failure.

**Q8. IT vs. IS — University Registration System**

*Short description: IT versus IS*

A university spends $2 million on a new registration software platform. After launch, students still cannot register because the academic advising workflow was not updated, staff were not trained on the new system, and course prerequisite rules were never entered. Which Chapter 2 distinction does this failure illustrate?

A. The university chose the wrong database platform
*Feedback: Incorrect — the scenario does not describe a platform selection error; it describes incomplete implementation.*

B. Confusing IT (the purchased software) with IS (the full system of technology, processes, data, and people)  ← ✓ CORRECT
*Feedback: Correct — Chapter 2 explicitly distinguishes IT (the technology tools) from IS (the complete system integrating technology with processes, data, and people). Buying software is buying IT; building a working registration system requires all five components.*

C. A failure of strategic alignment — the software does not match the university's mission
*Feedback: Incorrect — the software itself may be well-aligned; the failure is in implementation, not strategy.*

D. The registration software had a data quality problem with duplicate student records
*Feedback: Incorrect — the scenario describes missing processes, training, and data, not data quality issues with the software.*

**Hint:** What is the difference between buying technology tools and building a working system?

**Explanation:** Chapter 2 draws a critical distinction: IT (information technology) is the hardware and software — the tools. IS (information systems) is the complete system integrating technology, data, processes, and people to accomplish organizational goals. The university bought IT (software) but did not build the IS (processes, training, data rules).

**Points:** 1 | **Difficulty:** 3/5 | **ID:** BITM330-RAT2-Q8 | **Bloom:** Apply

**Q9. Strategic Alignment — Discount Retailer's ERP Choice**

*Short description: Strategic alignment*

A discount retailer whose strategy is "lowest possible prices through operational efficiency" is choosing between two ERP systems. System X excels at supply-chain cost optimization. System Y excels at personalized customer recommendations and loyalty programs. Applying Chapter 2's strategic alignment principle, which system should the retailer choose, and why?

A. System Y, because customer personalization is a modern business trend
*Feedback: Incorrect — following trends without strategic fit is misalignment, not strategic alignment.*

B. Both systems, because more technology is always better
*Feedback: Incorrect — Chapter 2 does not advocate for technology for its own sake; alignment means choosing technology that supports the specific strategy.*

C. System X, because its supply-chain optimization directly supports the retailer's low-cost operational efficiency strategy  ← ✓ CORRECT
*Feedback: Correct — strategic alignment means IT investments should directly support the organization's strategy. System X's supply-chain focus matches the low-cost strategy.*

D. Neither system — the retailer should build custom software instead
*Feedback: Incorrect — the scenario does not provide evidence that custom software is necessary; the question is about strategic fit between the options given.*

**Hint:** Strategic alignment: Does the IT investment directly support the organization's stated strategy?

**Explanation:** Chapter 2's principle of strategic alignment states that information systems should directly support organizational strategy. A discount retailer pursuing lowest possible prices needs systems that drive operational efficiency and cost reduction — exactly what System X provides. System Y's personalization features, while valuable for a different strategy, do not align with a low-cost strategy.

**Points:** 1 | **Difficulty:** 5/5 | **ID:** BITM330-RAT2-Q9 | **Bloom:** Evaluate

**Q10. IT Governance — Who Decides?**

*Short description: Governance decisions*

A mid-sized company is evaluating whether to allow individual departments to choose their own analytics tools or mandate a single company-wide platform. According to Chapter 2's IT governance principles, which question is most important to answer first?

A. Which analytics tool has the highest user satisfaction rating?
*Feedback: Incorrect — tool features and ratings are implementation details; governance is about decision rights first.*

B. Who should have the authority to make platform decisions — central IT, department heads, or a shared governance committee?  ← ✓ CORRECT
*Feedback: Correct — IT governance is fundamentally about decision rights: who decides what. Chapter 2 frames governance around establishing clear authority before evaluating specific solutions.*

C. What is the total cost of each analytics tool option?
*Feedback: Incorrect — cost is an evaluation criterion, not a governance question. Governance determines who makes the evaluation, not which tool is cheapest.*

D. How quickly can each department migrate its existing reports?
*Feedback: Incorrect — migration speed is an implementation concern, not a governance decision about authority and accountability.*

**Hint:** IT governance is about decision rights — who gets to decide what. Focus on authority, not features.

**Explanation:** Chapter 2 defines IT governance as the framework for deciding who makes which technology decisions and how those decisions are made. Before evaluating specific tools, costs, or timelines, the organization must determine decision rights: who has authority over platform selection. Governance establishes accountability before procurement begins.

**Points:** 1 | **Difficulty:** 3/5 | **ID:** BITM330-RAT2-Q10 | **Bloom:** Apply
